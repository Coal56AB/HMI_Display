# ESP32-S3: платформа экрана

Самостоятельный ESP-IDF 5.4.0 / PlatformIO `espressif32@6.10.0` проект для
ESP32-S3 с 4 МБ Flash (подтверждено загрузочным логом компактной платы).
Используется профиль DevKitC-1 с переопределённым размером Flash. PSRAM не требуется.
ILI9486 с Raspberry Pi SPI-адаптером, RGB565, 480×320 в альбомной ориентации;
тач XPT2046. Старый проект STM32 остаётся в `Firmware/BluePillHMI`.

## Подключение

Переподключить экран от STM32 к ESP32-S3. Значения GPIO и калибровка находятся в
`main/board_config.h`. Подписанные контакты GPIO на плате — не номера её ножек.

| Сигнал дисплея | ESP32-S3 GPIO |
|---|---:|
| SCK, T_CLK | 12 |
| MOSI, SDI, T_DIN | 11 |
| T_DO / MISO | 13 |
| LCD_CS | 10 |
| LCD_DC / RS | 9 |
| LCD_RST | 6 |
| T_CS | 8 |
| T_IRQ / PENIRQ | 7 |
| GND | Общая земля |

У имеющегося модуля экран питается от подписанного +5V, сигналы ESP32 — 3,3 В.
Внешняя W25Q16 этой сборке не нужна. Отключить её от общей SPI-шины или удерживать
её CS высоким. Хранилище `hmi_store` во Flash ESP имеет размер `0xe0000`;
настройки находятся по смещению `0xdf000`. При первом запуске после обновления
старые настройки автоматически копируются с абсолютного адреса `0x30f000`.
Раздел `songs` занимает `0x1f0000..0x400000`: десять композиций и один запасной
блок для записи без потери предыдущей версии. Старые пять физических блоков
сохраняют адреса и читаются как блоки 6–10 новой разметки. Обновлять нужно
прошивку и таблицу разделов; полное стирание Flash не требуется.
Стирание/запись сектора Flash может приостанавливать исполнение; приложение
должно сохранять настройки в момент, когда его выход остановлен.

GPIO19/20 зарезервированы под native USB. У компактной платы на фото цифры
1–13 обозначают GPIO; все подключения дисплея используют контакты 6–13.
UART0 GPIO43/44 (TX/RX) доступен для внешнего USB-UART.
На плате с одним USB-C для прошивки через USB удержать BOOT, нажать RESET,
отпустить RESET и BOOT, затем выбрать USB-порт загрузчика. На DevKitC можно
использовать отдельный USB-UART-разъём без этой ручной последовательности.
Контакт подсветки, если он отдельный, подключается
по схеме конкретного дисплейного модуля.

## Сборка и проверка

Из корня подмодуля:

```powershell
./Firmware/ESP32/build.ps1 -Environment template
./Firmware/ESP32/build.ps1 -Environment display
```

`BUILD_ESP32.cmd` запускает вторую команду. Требуется Python 3.11+; скрипт
использует найденный Python либо аргумент `-Python C:/path/python.exe` и при
необходимости устанавливает PlatformIO в `.build/platformio` на диске проекта.
Весь кэш и результаты сборки игнорируются Git и лежат в `.build`.

- `template`: цветные полосы и крестик в месте касания, без прикладного модуля.
- `display`: подключает `DisplaySrc/esp32/CMakeLists.txt`, если он есть в ветке;
  иначе запускает тот же тест полос. Платформа не зависит от родительского репозитория.

Для явно выбранной прошивки платы:

```powershell
./Firmware/ESP32/build.ps1 -Environment template -Upload -Port COM7
# После проверки полос и тача:
./Firmware/ESP32/build.ps1 -Environment display -Upload -Port COM7
```

Выбрать свой COM-порт USB-загрузчика либо USB-UART. Обычная сборка ничего не прошивает.
Результаты: `.build/esp32/<environment>/firmware.bin`, `bootloader.bin`, `partitions.bin`.
При ручной записи нужны все три: bootloader `0x0`, partitions `0x8000`, firmware `0x10000`.
Не записывать только приложение поверх неизвестной таблицы разделов.

Начальная частота SPI — 20 МГц. После проверки изображения можно попробовать
`HMI_LCD_CLOCK_HZ=40000000` в `board_config.h`; гарантии работы модуля на 40/80 МГц нет.
Пиксели передаются блоками через DMA с ожиданием прерывания, которое освобождает
процессор для других задач. Буфер не переиспользуется до окончания передачи.
Поворот задаётся `HMI_LCD_MADCTL=0x28`; XPT2046 сохраняет старую калибровку с
переводом координат в альбомную ориентацию. Проверить тач во всех четырёх углах.
Для голого ILI9486 без Pi-адаптера выбрать `HMI_LCD_RPI_ADAPTER=0` (RGB666).

`hmi_debug` доступен в отладчике: переданные пиксели/прямоугольники, время последнего
и самого долгого SPI-блока, сырые и экранные координаты касания.
Это время блока передачи, а не FPS всего интерфейса.

Передача LCD пропускает неизменившиеся блоки 16×8 по 64-битным сигнатурам.
Для MIDI-диаграммы прикладной GUI использует точное сравнение каждого пикселя,
а изменения передаёт вертикальными отрезками слева направо, обходя блочный фильтр.
Палитровый буфер MIDI занимает 50 400 байт; это точные цвета, не хеши.
Соседние изменившиеся блоки отправляются одной полосой; полный framebuffer не нужен.
Команды SPI передаются коротким polling-вызовом, пиксельные данные — через DMA.
При старте отображаются LCD READY, TOUCH READY, USB DETECT и READY.

Тач читает координаты и давление одним SPI-пакетом. Последняя команда возвращает
PD0=0 для PENIRQ; резервный опрос раз в 100 мс работает даже без IRQ.
Поведение PENIRQ описано в [даташите XPT2046](https://files.waveshare.com/wiki/common/XPT2046_Datasheet.pdf).

## Граница базового проекта

`scons_compat.py` исправляет копирование служебного объекта SCons 4.11.1
при создании ELF→BIN действий ESP-IDF. Без него сборка с `-v` может падать
с `TypeError: unsupported operand type(s) for +: '_Null' and 'str'`.
Исправление действует только в процессе сборки; установленный PlatformIO не меняется.

Для будущего отдельного коммита в `templates` предназначены **только**:
`Firmware/ESP32/`, `BUILD_ESP32.cmd`, добавленные правила `.gitignore`.
Здесь нет MIDI-кода и зависимости от музыкальной шкатулки.
Прикладная ветка добавляет `DisplaySrc/esp32/` и свой GUI.

Контракт GUI остаётся `Firmware/Api/display_api.h` версии 2.
Расширение добавляет исходники/зависимости в `hmi_sources`, `hmi_includes`,
`hmi_requires`, `hmi_defines` и реализует `display_init/event/step`.
Необязательные `hmi_module_start/tick/send` вызываются только задачей UI.
В базовой версии они пустые. UART-загрузчик ресурсов STM32 (`PCHR/PCHW`)
не перенесён; внешние ресурсы при необходимости записываются в раздел `hmi_store`.
