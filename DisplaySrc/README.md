# MusicBox · аппаратная сенсорная панель

480×320, STM32F103C8, ILI9486, XPT2046 и W25Q16. Модуль основан на `templates`,
API v2. Общая платформа и исходный проект Keil не изменены.

## Управление

- Шесть моторов в ряд, сплошные голубые шкалы. Подпись: нота либо частота.
- Нажатие шкалы или карточки открывает частоту, цифровую клавиатуру, ENABLE,
  STEP и DIR. Карточки высотой 48 px. Границы кнопок видимы.
- Композиция: пуск/пауза, позиция по нажатию/перетаскиванию, +/-10 секунд.
- MIDI: последние 8 секунд нот по высоте тона, цвета моторов, курсор.
  Кольцевой буфер хранит 96 сегментов; из UART принимаются реальные Note On/Off.
- Настройки: подпись и ширина шкалы 25/50/100%. На странице драйверов — микрошаг,
  SLEEP, RESET и ACTIVATE. «СТОП ВСЁ» постоянно доступна и срабатывает при нажатии.

Прошивка не генерирует искусственную музыку. При отсутствии STATE 1500 мс
индикация гаснет. Команды подтверждаются хозяином по UART, только фактическое
состояние из STATE меняет показания моторов.

## Сборка

Из корня репозитория дисплея:

```powershell
py -3 Scripts/Build/build_firmware.py
```

Keil: `E:/Keil_v5/UV4/UV4.exe` (переопределяется `--keil` или `KEIL_UV4`).
Результат — `Release/MusicBox/display.hex`. Сборка не прошивает плату.
Ресурсы встроены, `resources.bin` не нужен. Последний сектор W25Q16
`0x1FF000` выделен под настройки с CRC. Запись отложена на 5 секунд и выполняется
при остановленном проигрывателе. При повреждении записи используются значения
по умолчанию. Калибровка XPT2046 сохранена из templates, пределы под конкретную
панель задаются в `Firmware/BluePillHMI/Config/project_config.h`.

## Скорость и память

Платформа остаётся в родных 320×480; модуль поворачивает изображение и касания:
логическое `(x,y)` соответствует физическому `(319-y,x)`.
Полного framebuffer нет. Два буфера по 960 RGB565 пикселей занимают 3840 байт.
Каждый `display_step` передаёт не более 960 пикселей; между передачами платформа
опрашивает сенсор. RX IRQ только складывает байты в очередь.

Шкала обновляется прямоугольником разности старой и новой высоты. Подписи
перерисовываются отдельно; карточки не перерисовываются из-за изменения частоты.
Узкая шкала сохраняет полную зону касания. MIDI перерисовывается только при
новых данных, не чаще 5 раз в секунду. Полные перерисовки тоже разбиты на полосы.
Нативная проверка шести изменившихся частот: 13 500 пикселей при ширине 100% и
9 396 при 25%, включая подписи. Это подсчёт передач, не измерение FPS на железе.

## Симулятор того же C-кода

Python 3.7+, PySide2, MinGW GCC. Путь GCC: `CC`, PATH или `C:/mingw64/bin/gcc.exe`.

```powershell
py -3 DisplaySrc/Scripts/test.py
py -3 DisplaySrc/Simulator/main.py
py -3 DisplaySrc/Simulator/main.py --page midi --screenshot midi.png
```

`SIMULATOR.cmd` запускает эту программу. Свой Python: `MUSICBOX_PYTHON`.
Код картинки и касаний берётся из `src/music_box.c`; Python только реализует
виртуальные LCD, XPT2046, Flash и отвечающий по UART контроллер. COM-порты
симулятор не открывает. Окно увеличено вдвое, PNG сохраняется в 480×320.

## UART и MusicMotorStudio

Контракт: [PROTOCOL.md](PROTOCOL.md). Панель — отдельная плата с отдельным UART;
её протокол не является NOTE_SET моторного контроллера.

```powershell
py -3 DisplaySrc/Host/studio.py --display-port COM8 --motor-port COM6 --studio-dir E:/hobby/music_motor
```

Запускает исходники Studio с панелью на втором USB–UART. Без `--motor-port`
соединение с моторами выбирается в окне Studio. Моторным портом владеет только
существующий Client. Команды панели вызывают существующие обработчики Studio.
Не соединяйте двух передатчиков с RX моторного контроллера одновременно.

Дорожка этого адаптера показывает наблюдаемые ноты моторов с опросом 100 мс,
не все сырые MIDI-события. Для точной дорожки контроллер ESP32 может отправлять
MIDI_EVENT напрямую. Физический USB-MIDI обрабатывается на ESP32; UART-контракт
панели не добавляет USB Host к STM32. Код ESP32 развивается в родительском проекте.

## Проверки

`DisplaySrc/Scripts/test.py`: поворот и касания, числовой ввод, seek, STOP,
CRC, переполнение RX, ACK/повторы, тайм-аут и переполнение часов, Flash, MIDI,
границы всех экранов. Исполняется настоящий C-код.

`DisplaySrc/tests/test_host.py`: UART, UTF-8 и повторные команды, настоящий класс
MusicMotorStudio с виртуальным моторным контроллером, STATE и STOP/ACK.
Нужен соседний MusicMotorStudio с зависимостями.

`Scripts/Check/check_platform_boundary.py`: сборка другой реализации GUI и
проверка побайтовой неизменности платформы. На физической плате эта версия
пока не проверена.
