# Музыкальная шкатулка: экран + USB-MIDI на ESP32-S3

Этот модуль расширяет [базовый ESP-проект](../../Firmware/ESP32/README.md).
Собирается окружением `display`, полностью из содержимого подмодуля.
Алгоритм `music/`, USB-host и заголовки протокола находятся рядом с исходниками.

## Схема

**USB-MIDI инструмент → ESP32-S3 с экраном → UART → STM32 → драйверы моторов.**

Экран и тач подключить по таблице базового проекта. Для MIDI:

| Сигнал | Подключение |
|---|---|
| USB D− | GPIO19 |
| USB D+ | GPIO20 |
| USB VBUS | Питание 5 В инструмента со стороны хоста |
| UART TX/RX ESP | GPIO4 (контакт «4») ↔ PA2 TX/RX USART2 моторной STM32 |
| Подтяжка линии UART | Один резистор 1 кОм от общей линии к 3,3 В |
| GND | Общая земля ESP, STM32 и питания |

На компактной плате с фотографии один USB-C: в рабочем режиме он занят инструментом.
Для прошивки отключить инструмент, подключить ПК, зажать BOOT, нажать и отпустить
RESET, затем отпустить BOOT. Выбрать появившийся USB-порт загрузчика. При запуске с ПК включается USB-симулятор, без ПК — MIDI Host.
После смены кабеля нажать RESET или удержать BOOT 2 секунды и отпустить.
Перепрошивать ESP для переключения USB не нужно.
Для консоли во время игры можно подключить отдельный USB-UART с уровнями 3,3 В
к контактам TX/RX (UART0) и GND. Он не нужен для передачи нот в STM32:
для неё используется отдельный однопроводный UART1 на контакте «4».
Проверить схему своей платы: ESP не создаёт 5 В VBUS самостоятельно.
Питание инструмента должно поступать через подходящий источник/ограничитель тока;
не соединять два независимых источника 5 В напрямую. Код аппаратного выключателя
VBUS выключен (`USB_VBUS_ENABLE_PIN=-1`). Wi-Fi/Bluetooth не запускаются.

Моторная STM32 использует общую сборку **LIVE_MIDI_MODE=1** (теперь по умолчанию),
`MIDI_INSTALLED_MASK=0x3f`. USART2 для ESP: **PA2 TX/RX, 460800 8N1, полудуплекс**.
Оба конца настроены с открытым стоком; внешняя подтяжка нужна, внутренней
подтяжки ESP недостаточно для расчётной скорости. PA3 и GPIO5 для связи не нужны.
Прошить обе платы: старый двухпроводный протокол с этой сборкой несовместим.
Компьютер подключается одновременно через CH340 к USART1: **PA9 TX / PA10 RX,
115200 8N1**. Music Motor Studio и её протокол остаются прежними.
Валидные команды ПК удерживают приоритет; через 2 секунды без них моторы
останавливаются и управление снова доступно ESP. При активном ПК MIDI
игнорируется, ручные изменения с экрана отклоняются; «СТОП ВСЁ» доступен всегда.
USB ESP обслуживает инструмент или симулятор экрана, а не пересылку команд ПК.

## Поведение

- При внешнем питании запуск без USB разрешён: обнаружение ПК ограничено примерно
  одной секундой, после чего запускается MIDI Host. Отсутствие инструмента или STM32
  не блокирует интерфейс. Аппаратный холодный запуск пока не проверен.
- LCD инициализируется первой операцией `app_main()`. Затем видны этапы TOUCH,
  STORAGE, ASSETS, UART LINK, USB DETECT, MIDI HOST/USB PC, INTERFACE. Задержки
  сброса/выхода LCD из сна остаются необходимой частью его инициализации.
- ESP — ведущая однопроводной линии. Запрос и ответ обёрнуты в кадр с CRC и номером.
  STM32 начинает ответ только по запросу и не позднее 3 мс после его приёма;
  ESP ждёт ответ до 20 мс. Обычный пустой опрос идёт через 5 мс, новые команды
  и MIDI будят задачу сразу. Во время ответа новые MIDI-состояния объединяются.
  Передача освобождает линию после последнего стоп-бита. Физические задержки и
  фронты сигнала ещё нужно проверить на платах.

- Приём USB-MIDI 1.0 bulk IN, выбор до шести голосов прежним алгоритмом.
- Набор нот отправляется при изменении и повторяется каждые 50 мс. При потере
  потока STM32 останавливается по прежнему watchdog 300 мс.
- «Пауза» и «СТОП ВСЁ» выключают выход нот, отправляя пустой NOTE_SET.
  Выход остаётся выключенным до «Играть»/«Включить MIDI»; ноты требуется нажать заново.
  Это прекращение нот/ENABLE через существующий протокол, не команда аппаратного RESET/SLEEP.
- Поддерживаются Note On/Off, sustain и прежняя обработка MIDI-контроллеров.
  Отключение USB снимает ноты; переполнение входной очереди также ставит выход на паузу.
- Повтор команды интерфейса не выполняет переключение второй раз.
- Корректные состояния основной STM32 по UART имеют приоритет над USB-симулятором
  и локальной историей MIDI. Через 500 мс без UART-состояний выбирается свежий резервный источник.
- Без обратной связи STM32 в MIDI Host показываются логические голоса отправленного
  набора (заголовок «USB MIDI»), а не подтверждённые состояния физических моторов.
- Полный GUI доступен всегда. Команды направляются текущему источнику; неподдерживаемые
  команды возвращают «недоступно». При активном MIDI стоп/пауза также выключают
  генератор NOTE_SET, чтобы следующий пакет не запустил моторы снова.
- Снимок локального MIDI публикуется после помещения полного пакета в очередь UART.

USB-задачи: ядро 0, приоритеты 22/21; MIDI: ядро 1, приоритет 20;
UI: ядро 1, приоритет 3. Передача LCD через DMA не блокирует обработку MIDI.
Очередь UI ограничена: при переполнении история сбрасывается до актуального состояния,
а музыкальный поток продолжает работать. Мелкие события могут отсутствовать на графике
при перегруженном UI; это не задерживает NOTE_SET.

GUI рисует полосами 16 строк, без программного поворота пикселей. Запрос обновления
панорамы — раз в 50 мс, но незавершённая перерисовка не начинается заново.
Это не обещание 20 FPS: достижимая скорость зависит от площади изменений и SPI.
PSRAM и внешний W25Q16 для этой реализации не требуются.

Настройки экрана сохраняются после 5 секунд покоя на паузе/после остановки,
чтобы запись Flash не выполнялась во время MIDI-игры.
Обычный симулятор не менялся: он не моделирует физическое время SPI.

## Сборка

`./Firmware/ESP32/build.ps1 -Environment display`

USB-симулятор: `USB_SIMULATOR.cmd`, подробности в `Docs/usb-controller-simulator.md`.
