# MusicBox HMI UART v1

В профиле ESP32 используется однопроводная оболочка `half_duplex_wire.h`, 230400 бод. Музыкальное состояние и сглаживание вычисляет STM32. Старые переходы индикации из коммита ESP `00e979e` перенесены на STM32: минимум 1000 мс от начала отображаемой ноты и ещё 1000 мс после более позднего из минимума и отпускания. ESP только отрисовывает результат.

Текущий STATE v2: 86 байт каждые 50 мс. Первые 50 байт имеют описанную ниже структуру, но version=2. После них идут шесть отображаемых записей по 6 байт: `u8 flags, u8 note, u32 frequency_mHz`. Их bit1 означает подсветку; остальные биты соответствуют ENABLE/DIR. Фактический STEP, нота и частота остаются в первых шести записях. Общий bit6 и фактический моторный bit3 (`display_hold`) используются алгоритмом STM32, а не таймерами ESP. STATE v1 читается для совместимости без локального сглаживания. Новые прошивки STM и ESP устанавливаются вместе.

Живые события: команда 0x56, первый байт — подключение USB-MIDI (0/1), затем записи по 10 байт (`time_ms:u32, address:u8, type:u8, note:u8, velocity:u8, pin:u8, priority:u8`). Для USB pin и priority нулевые. Type: 0 On, 1 Off, 2 CC, 4 Reset; bit7 завершает группу USB transfer. Address: порт в старшей тетраде, канал в младшей. STM отвечает 0x57 с одним байтом результата и тем же SEQ. ESP повторяет неподтверждённый пакет, STM не исполняет повтор второй раз. Состояние экрана не формируется по отправленным событиям — оно принимается от STM.

Сохранение: SONG_BEGIN прежних 48 байт + байт 1 обозначает новый формат. При проигрывании такие записи идут в команду двигателя 22; команда 23 с позицией перемотки в мс передаётся после CLEAR. ACK команды 22 возвращает входные кредиты, рассчитанные по свободному месту выходной очереди STM. Старые 48-байтовые заголовки используют команду 18. Ниже приведён базовый протокол отдельной панели.

115200, 8N1. PA9 TX, PA10 RX, общий GND, уровни 3,3 В. Отдельный UART панели;
не соединять с передатчиком на линии моторного контроллера.

Кадр: `A5 5A LEN SEQ CMD PAYLOAD CRC_LO CRC_HI`. LEN 0–240. CRC16-CCITT,
полином 0x1021, начальное 0xFFFF, по LEN..PAYLOAD. Числа LE.

## Контроллер → панель

| CMD | Payload |
|---|---|
| 0x40 STATE | 50 байт каждые 100 мс |
| 0x41 TITLE | до 48 байт UTF-8 без завершающего нуля |
| 0x42 MIDI_EVENT | u32 time_ms, u8 motor, u8 note, u8 velocity |
| 0x43 MIDI_CLOCK | u32 time_ms |
| 0x51 ACK | один байт 0=принято, 1=недоступно, 2=неверное значение; SEQ команды |

STATE: `u8 version=1, u8 flags, u8 sleep, u8 reset, u8 microstep_raw, u8 mask,
u32 position_ms, u32 duration_ms`, затем шесть записей `u8 flags, u8 note,
u32 frequency_mHz`. 440 Гц = 440000 мГц.

Общие flags: bit0 связь с моторами, bit1 проигрывание, bit2 пауза, bit3 MIDI подключён.
Флаги мотора: bit0 ENABLE, bit1 STEP, bit2 DIR. Моторы 0–5, note 0–127 или 255.

MIDI_EVENT: velocity=0 закрывает ноту, >0 открывает. Новая нота закрывает прежнюю
на том же моторе. Время монотонное для сессии. MIDI_CLOCK с меньшим временем
начинает новую историю. Отправляйте точные события для коротких нот между STATE.

## Панель → контроллер

Живой MIDI через ПК: `0x56`, payload `u8 connected`, затем 0–20 событий
по 10 байт: `u32 timestamp_ms, u8 source_channel, u8 operation, u8 note,
u8 velocity, u16 reserved=0`. Operation: 0 Note On, 1 Note Off, 2 CC, 4 Reset;
бит 7 закрывает группу событий. ESP пересылает кадр из USB на STM32 независимо
от текущего источника GUI. `0x57` с одним байтом результата и тем же SEQ идёт
обратно на ПК (0 — принято; 12 — STM32 занята). ПК ожидает ACK, повторяет
неподтверждённый кадр через 100 мс и посылает пустой connected=1 как heartbeat.
При закрытии передаётся connected=0. UI-пакеты `0x42` моторы не запускают.

0x50 ACTION: `u8 action, u8 motor, u32 value`.

| Action | Значение |
|---|---|
| 0 STOP_ALL | немедленная остановка всех |
| 1 PLAY_PAUSE | запуск/пауза/продолжение композиции |
| 2 SEEK | мс, сохранять состояние паузы |
| 3 FREQUENCY | 20000–4000000 миллигерц |
| 4 ENABLE | 0/1 |
| 5 START_STOP | STEP 0/1 |
| 6 DIR | 0/1, корректная остановка/возобновление при смене |
| 7 MICROSTEP | raw 0/1/2/3/7 |
| 8 SLEEP | 0/1 |
| 9 RESET | остановить STEP, снять ENABLE и включить RESET |
| 10 ACTIVATE | снять RESET/SLEEP, не запускать моторы |

Вид подписи и ширина сохраняются локально, UART-команда не нужна.
Панель ожидает одну команду; максимум 3 передачи того же кадра с интервалом
300 мс. STOP_ALL заменяет ожидающую команду новым SEQ.

Контроллер распознаёт повтор `(SEQ, payload)` в течение 2 секунд и возвращает
прежний ACK, не повторяя действие. Особенно важно для PLAY_PAUSE. ACK означает
принятие, фактическое состояние приходит в STATE. Ошибки исполнительной платы
не должны подменяться оптимистичными показаниями.

Битый CRC/версия/длина игнорируются. 1500 мс без STATE гасят индикацию и
блокируют команды, кроме STOP. Физическая остановка при обрыве — ответственность
watchdog моторного контроллера.
