# Проверка сжатия и сенсорной оболочки

Дата: 2026-09-07. Исходный commit: `0c1e2584bec246b2242bb5386c227571ed9c98f5`.
Компилятор: MinGW-w64 GCC 8.1.0, x86_64, `-std=c99 -Os -Wall -Wextra -Werror`.

## Размеры объектных секций

Сумма `.text*` и `.rdata*`/`.rodata*`, без host CRT, executable headers, тестового framebuffer, unwind-секций и кода платы. Оба варианта измерены одним компилятором через `Scripts/measure_size.py`.

| Часть | Исходно, байт | После, байт |
|---|---:|---:|
| gfx + шрифты | 226 112 | 184 000 |
| Сцены, таблицы и имена | 260 320 | 141 536 |
| Интерпретатор сцен | 1792 | 2144 |
| Частичные обновления | 2400 | 2448 |
| Динамические значения | 4880 | 4880 |
| Итого рендерер | **495 504** | **335 008** |
| Новая сенсорная оболочка | — | 18 512 |
| Итого с оболочкой | **495 504** | **353 520** |

Экономия рендерера — **32,4%**, с добавленной оболочкой — **28,7%**. Оценка const-ресурсов через `hmi_static_data_bytes()` — 319 084 байта (включает таблицы сцен, glyph metadata и bitmap, без кода).

Пиксельный буфер: **10 240 → 4096 байт**. Статическая RAM рендерера: **10 880 → 4736 байт**. `sizeof(HmiUi)` на x64 host — **1344 байта**, включая очередь. Итого рабочие постоянные данные рендерера и оболочки — 6080 байт, без стека, данных графиков/журнала, драйвера и протокола. На ARM размеры структур и библиотек отличаются.

## Сохранение изображения

Исходный рендерер отдельно собран из нетронутого checkout и выполнен тем же тестовым harness:

- 47 исходных сцен;
- 47 вариантов с динамическими значениями, часами, графическими выборками и журналом;
- 47 вариантов с узким невыравненным прямоугольником обновления;
- 223 проверяемых кодовых позиции (включают все 192 символа каждого исходного шрифта и fallback), 14 запрошенных размеров, оба начертания, два фрагмента по высоте.

**12 629 контрольных сумм совпали.** Дополнительно объединённые RGB565-выходы исходной и новой версий сравнивались по SHA-256; оба:

`70BD8D4EE16C96FFC92515C39BF2847E35CBC765772E4B2E6CE97DC40FC3230B`

Сохранены все 4224 глифа в 22 наборах, все 47 сцен и 9598 примитивов текущего checkout. Ранее README сообщал другие количества и размеры; здесь приведены фактически проверенные данные.

## Другие проверки

- `make -j2`, `make test` — прошли; Windows-эквивалент — `mingw32-make` с явным путём Python.
- 47 сцен восстановлены из прямоугольников 73×37, включая края и пересечения границ внутренних полос: совпадают с полным кадром.
- Частичное обновление часов совпадает с полной перерисовкой.
- При буфере 640 пикселей вместо стандартных 2048 повторно совпали все 12 629 контрольных сумм.
- Сенсор: переходы, ввод/подтверждение, недопустимые значения, отмена, вложенный редактор/отмена родительского окна, модальность, время, ROM, дребезг, отмена при движении, переполнение миллисекундного счётчика, пользовательская зона, очередь и её переполнение, отрисовка всех типов окон.
- Пример STM32 backend компилируется в объектный файл с теми же строгими флагами; функции платы остаются внешними.
- Runtime-превью просмотрены визуально; зоны ввода числовых параметров и основных диалогов сверены с координатами экспортированных примитивов. Для восьми датчиков добавлена компактная runtime-раскладка с видимыми кнопками сохранения/отмены.

Исходные HTML-эталоны, генератор HTML и прежние тесты в checkout отсутствовали. Поэтому это подтверждение сохранения исходного **C-изображения**, а не повторная проверка HTML ↔ C.

ARM ELF, расход стека и скорость настоящего STM32/SPI не измерены: конкретная плата/драйвер и подключённое оборудование не предоставлены. Сжатие добавляет декодирование шаблонов; проверка границ блоков позволяет пропускать блоки вне полосы, но частота кадров на STM32 требует измерения.
