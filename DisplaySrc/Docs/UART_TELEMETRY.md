# UART-терминал и телеметрия

Запуск: **SIMULATOR.cmd** в корне проекта либо **START.cmd → Открыть терминал**.
Откроется браузер с моделью из `HMI_F407_F103_Simulator(5).html` и панелью UART.
Исходный файл в Downloads не изменён; рабочая копия — `Scripts/uart_simulator.html`,
адаптер — `Scripts/uart_bridge.js`, локальный UART-сервер — `Scripts/uart_server.py`.
Требуются Python 3.7+ и `pyserial==3.5`; установка: `py -3 -m pip install pyserial==3.5`.

USB–UART 3,3 В: TX адаптера → PA10, RX → PA9, GND → GND. 115200, 8N1.
Выберите COM-порт и нажмите «Подключить». Статус «На связи · ACK» подтверждает ответ платы.
Без подключения работают все локальные органы управления исходного HTML.
Перед прошивкой отсоедините порт кнопкой UART «Отключить».

Основная сборка — **ExternalFlash**. После обновления необходимо записать и прошивку
STM32, и `DisplaySrc/Assets/hmi_assets.bin`
через **START.cmd → Загрузить ассеты**.

## Управление

- Одна кнопка **Заряд / Разряд**. Заряд через 150 Ом, ёмкость **3 мФ**:
  τ = 0,45 с, шунтирование при 98 %, примерно 1,76 с из полностью разряженного состояния.
- Одна кнопка **Пуск / Стоп**. Пуск после готовности; разгон и торможение из исходной модели.
- Галочка справа выбирает **разряд через инвертор**. Сеть отключается, DC и инвертор
  подсвечиваются штатным жёлтым фоном. Мощность по умолчанию 30 Вт.
  Нажатие «Стоп» во время этого разряда оставляет только самостоятельный разряд.
- Без галочки сеть отключается, напряжение падает через эквивалентную утечку
  (по умолчанию 100 кОм, можно изменить). Предзарядный резистор в этот разряд не включён.
- Энкодер: колесо или перетаскивание меняет черновик; короткое нажатие применяет;
  удержание 0,5 с выбирает следующий параметр. Черновик и применённое значение
  передаются на физический дисплей отдельно.
- Режимы U/f, SF, VF, параметры, журнал, пауза/масштаб/перемещение/курсор графиков
  работают в браузере по коду предоставленного HTML.
- На физическом дисплее настройки отображения открываются двойным нажатием,
  справка разбита на страницы с карточками и цветовой легендой.

## Графики

Передаются исходные каналы модели: фазные токи и DC; частоты и модуляция;
ограничение тока; D/Q. На канал приходится **240 точек**, передаваемых частями.
Дисплей применяет канал только после получения всех частей. Масштаб времени и
выбранная вкладка сообщаются дисплеем в ACK. Оформление использует исходные
сцены, сетку и карточки статистики; дополнительные фоны для живых графиков
убирают только демонстрационные кривые и числа.
Частота обновления зависит от UART и скорости отрисовки дисплея.

Это модель для отладки HMI, а не силовой контроллер. Токи, температуры и движение
рассчитываются моделью HTML. Часы и даты журнала синхронизируются пакетом TYPE 6 от ПК.

## Протокол PCH UART v1

Все многобайтные поля little endian. Кадр: `A5 5A TYPE LEN PAYLOAD CRC16`.
LEN — длина PAYLOAD, CRC — CRC-16/CCITT-FALSE (`poly=0x1021`, `init=0xffff`,
без отражения и xorout), считается по заголовку и payload, CRC передаётся младшим байтом вперёд.
Контрольный вектор `123456789` → `0x29b1`.

### TYPE 1: дисплей → ПК, событие, LEN=24

`sequence:u32, event_type:u8, reserved:u8, id:u16, value:f32, flags:u32, data:8 bytes`.
Это существующий формат `HmiEvent`. VALUE_CHANGED=1, ID 0/1/2 — модуляция/Гц/лимит;
SETTINGS_CHANGED=2 ID10 — режим привода. CUSTOM=10 ID400 — выбор строки для энкодера,
value=0/1/2 (sequence для этого уведомления равен 0).
Остальные события видны в журнале терминала; не все настройки влияют на упрощённую модель.

### TYPE 2: ПК → дисплей, телеметрия, LEN=104

`sequence:u32, state:u8, mode:u8, selected:u8, flags:u8, uptime_ms:u32, values:23*f32`.

state: 0 стоп, 1 заряд, 2 готов, 3 работа, 4 регулирование, 5 авария.
mode: 0 U/f, 1 SF, 2 VF. selected: 0/1/2.
flags: bit0 инвертор включён, bit1 регулирование, bit2 уставка достигнута,
bit3 сеть подключена, bit4 резистор шунтирован, bit5 самостоятельный разряд,
bit6 разряд инвертором, bit7 зарезервирован=0. При разряде state=0 и соответствующий флаг.
uptime_ms пока принимается без отображения.

Порядок float-полей:

1. Напряжение сети, В.
2. Частота сети, Гц.
3. Напряжение DC, В.
4. Ток предзаряда, А.
5. Прошедшее время предзаряда, с.
6. Температура выпрямителя, °C.
7. Температура резистора предзаряда, °C.
8. Температура DC-звена, °C.
9. Температура инвертора, °C.
10. Температура двигателя, °C.
11. Задание модуляции, %.
12. Фактическая модуляция, %.
13. Заданная частота ротора, Гц.
14. Фактическая частота ротора, Гц.
15. Заданный лимит тока, % номинального.
16. Фактический ток, % номинального.
17. Выходное напряжение, В.
18. Выходной ток, А.
19. Выходная мощность, кВт.
20. Частота ротора, Гц.
21. Частота статора, Гц.
22. Скольжение, %.
23. Нагрузка двигателя, %; −1 означает отсутствие данных.

Пакет применяется целиком между проходами рендера. NaN, Infinity, недопустимые enum
и числа вне ±100000 отклоняются. До первого пакета отображается «СТОП». Спустя 10 с без валидной телеметрии
появляется предупреждение о связи и запись в журнале. Авария контроллера — отдельное событие.

### TYPE 3: ПК → дисплей, снимок канала графика, LEN=12+2*N

`sequence:u32, page:u8, channel:u8, minimum:i16, maximum:i16, N:u8, scale:u8, samples:N*i16`.
page: 0 мощность, 1 скорость, 2 ограничение, 3 D, 4 Q; channel: 0..3, N: 0..48.
maximum>minimum. scale=0/1/2 означает 10/100/1000 отсчётов на единицу канала.
Первая точка слева, последняя справа. Несоответствующая вкладка и остановленная запись
не изменяют сохранённый график. Каждый пакет полностью заменяет один канал.

### TYPE 4: дисплей → ПК, подтверждение, LEN=11

`sequence:u32, status:u8, graph_page:u8, graph_flags:u8, ms_per_division:u32`.
status: 0 принят, 1 неверные поля, 2 график пропущен (вкладка/пауза).
graph_flags: bit0 запись включена, bit1 страница графиков открыта.
Подтверждаются пакеты 2/3/5/6/7 с корректным CRC; повреждённые кадры игнорируются.

У отправителя только один неподтверждённый пакет, максимум 114 байт.
Терминал повторяет его через 2 с, максимум три повтора. Повторный снимок безопасен:
телеметрия и канал заменяются, никаких силовых команд дисплей по этим пакетам не исполняет.
UART ISR только кладёт байты в кольцевой буфер, отрисовку и разбор не вызывает.
Runtime-команда загрузчика `PCHR` распознаётся вне кадров, не внутри payload.

### TYPE 5: черновик энкодера, LEN=17

`sequence:u32, pending_mask:u8, modulation:f32, frequency:f32, limit:f32`.
Маска bits0..2 показывает изменённые задания, bits3..5 — переходный процесс каждой строки; единицы %, Гц, %.
Применённые значения приходят отдельно в TYPE 2.

### TYPE 7: часть канала из 240 точек, LEN=14+2*N

`sequence:u32, page:u8, channel:u8, start:u8, N:u8, scale:u8, cursor:u8,
minimum:i16, maximum:i16, samples:N*i16`.
N≤47, cursor=0 для истории или 1…240 для положения линии развёртки, start+N≤240. Части идут последовательно от start=0.
Повтор последней части допустим. Готовый канал отображается атомарно после точки 239.
scale имеет тот же смысл, что в TYPE 3.

Проверка протокола: `py -3 Scripts/check_uart.py` (нужен MinGW в C:/mingw64).
Она отправляет Python-пакеты в реальный C-парсер прошивки и проверяет ACK,
ошибку CRC, побайтовую фрагментацию, черновики, повтор частей, 240 точек и тайм-аут.

### TYPE 6: время журнала, LEN=12

`sequence:u32, local_epoch_seconds:u32, reserved:u32=0`.
ПК передаёт календарное местное время в секундах от 1970-01-01.
После холодного включения до синхронизации записи помечаются неизвестной датой;
они сохраняются при упаковке по дате и удаляются только полной очисткой.

## Постоянный журнал

W25Q16: ресурсы занимают начало Flash; **0x128000…0x1FFFFF** зарезервированы
для журнала (864 КиБ). Два банка по 432 КиБ; в активном **27 392 записи** по 16 байт.
Запись содержит время, код, ID параметра, значение и CRC с маркером завершения.
Это год при среднем числе до 75 событий в день или 27 дней при 1000 событиях в день.
Записываются переходы алгоритма ПЧ (заряд, готовность, пуск, остановка, разряд),
аварии, потеря/восстановление связи и обслуживание хранилища. Навигация, выбор
энкодера и правки уставок не записываются; старые записи этих действий скрыты.
Переходы между работой и регулированием не создают повторных событий пуска.

Фильтр выбирает информацию, предупреждения и аварии. Страницы читаются из Flash.
При заполнении 90 % на главном экране появляется предложение упаковать журнал.
Кнопка «Очистить» или это предложение открывают выбор: **«Очистить всё»**
или **«Очистить по дату»**. Во втором режиме вводится дата **ГГММДД**:
например, 260831 — удалить по 31.08.2026 включительно. Оба режима требуют подтверждения. Оставшиеся записи переносятся в начало другого банка;
старый банк сохраняется до атомарного завершения. Запись продолжается в освобождённом месте.
Обновление ассетов через загрузчик журнал не стирает.

Проверка: `py -3 Scripts/check_journal.py` — NOR-модель, заполнение, перезапуск,
фильтры, упаковка, очистка и обрыв питания в 120 точках операции.

### TYPE 8: автоопределение, LEN=26

`sequence:u32, progress:u8, state:u8, Rs:f32, Rr:f32, Lls:f32, Llr:f32, Lm:f32`.
state=1 — измерение, 2 — завершено; progress=0…100; сопротивления в Ом, индуктивности в мГн.
Принимается только после запуска автоопределения. Симулятор выдаёт демонстрационные результаты.

## Графики и индикация длительных операций

На ПК выделено по 600000 отсчётов на канал (10 минут при 1 кГц). Новый пуск очищает историю.
Дисплей хранит текущее окно по 240 точек на канал. В работе линия идёт слева направо;
изменённая полоса перерисовывается без сдвига всего графика. Статистика каналов обновляется не чаще 2 Гц.
На паузе кнопки < и > перелистывают накопленные окна.

При загрузке показаны этапы LCD, Flash, записи/проверки ресурсов и журнала.
Очистка и упаковка журнала показывают прогресс стирания и переноса записей.
Яркость скрыта: у текущей разводки нет программно управляемого вывода подсветки.

Загрузка системы оформлена текстовой консолью без привязки к ПЧ: этапы, проценты и OK. При ошибке выводятся причина и инструкция; загрузчик UART остаётся доступен. Шрифт консоли встроен в прошивку и не зависит от ассетов. Проверка ресурсов выдаёт 100% только после успешного CRC. Проверки отказов: `py -3 Scripts/check_storage.py`.

## Единый контракт отрисовки (09.09.2026)

TYPE 9, LEN=16: `sequence:u32, states:12*u8`. Каждый state: 0 выключен,
1 норма, 2 предупреждение/переход, 3 авария. Порядок: напряжение сети,
частота сети, выпрямитель, предзаряд, DC, инвертор, двигатель, затем пять температур
(выпрямитель, предзаряд, DC, инвертор, двигатель). Пороговые решения принимает
контроллер. Экран только выбирает заданный цвет. При аварии сети модель контроллера
передаёт выключенное состояние остальным блокам. Без TYPE 9 подсветка не включается.

TYPE 10, LEN=35: `sequence:u32, page:u8, cursor:u8, count:u8, scales:4*u8,
ranges:4*(min:i16,max:i16), samples:4*i16`. cursor=1…240, count=1…4;
scales: 0 ×10, 1 ×100, 2 ×1000. Обновляется один отсчёт каждого канала.
После первой инициализации обновляются только 3–4 столбца пикселей (линия и
соседние отрезки), максимум 712 пикселей; статистика отдельно раз в секунду.
Для просмотра истории используется TYPE 7. Короткое окно захватывается целиком
перед проходом линии, затем постепенно обновляется слева направо: скорость
рисования не подменяет физический масштаб времени захваченных отсчётов.

Масштабы: 2, 5, 10, 20, 50, 100, 200, 500 мс/дел; 1, 2, 5 с/дел.

EXE отображает RGB565 из того же C-кода и парсера UART, что и прошивка.
HTML используется только как модель контроллера, его экран пользователю не показывается.
`Scripts/build_simulator.cmd` собирает DLL и EXE с ресурсами; `renderer-build.json`
содержит контрольные суммы исходников и ассетов. Проверки: `Scripts/check_rendering.py`
сравнивает частичное обновление с полным и ограничивает количество выведенных пикселей.

В настройках защиты отдельная страница «Защиты сети»: восемь уставок U/f для предупреждения и аварии сверху и снизу. ID параметров 48…55 передаются контроллеру обычным событием изменения параметра; локальный рендерер не применяет эти пороги к телеметрии.

TYPE 11, LEN=8: `sequence:u32, history_offset_ms:u32`. Смещение правой границы относительно последней записанной точки; подписи оси учитывают его. Стрелки истории перемещают окно на 2,5 деления (половину ширины). После стопа сохраняется левый участок до курсора, старый правый участок скрывается.
