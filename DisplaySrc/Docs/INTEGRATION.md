# STM32: UI, сенсор и сменный драйвер дисплея

В библиотеке теперь два независимых уровня:

1. `hmi_render_*` — прежний рендерер 47 сцен с уплотнёнными данными. Выход RGB565 совпадает с исходной версией.
2. `hmi_ui_*` — новый контроллер взаимодействия: координаты → действие → состояние/отрисовка → очередь событий. Он накладывает текущие значения и настройки поверх сцен.

Ни один уровень не включает HAL, регистры SPI/FSMC, чтение XPT2046 или конкретный протокол связи.

## Минимальное подключение

Добавить все `.c` из `src` и `ThirdParty/tinf/tinflate.c`, пути `include` и `ThirdParty/tinf`. Профили памяти и инициализация хранилища описаны в [PROFILES.md](PROFILES.md). Генераторы Python и `Assets/asset_source.json.gz` в прошивку не входят.

```c
#include "hmi_ui.h"

static HmiUi ui; // не на стеке функции, которая завершится

void init_ui(void) {
    hmi_ui_init(&ui, (HmiDisplay){ lcd_flush_rect, NULL });
    hmi_ui_render(&ui);
}

void foreground_loop(void) {
    // До этого: чтение XPT2046, калибровка и поворот координат.
    hmi_ui_touch(&ui, x, y, pressed, HAL_GetTick());
    hmi_ui_render(&ui);

    HmiEvent event;
    while (hmi_ui_poll_event(&ui, &event)) {
        // Например, event.type == HMI_EVENT_VALUE_CHANGED:
        // event.id == HMI_VALUE_ROTATION_HZ, event.value == 25.0f.
        protocol_enqueue_ui_event(&event);
    }
}
```

Здесь `lcd_flush_rect` и `protocol_enqueue_ui_event` — функции проекта платы. Компилируемый пример адаптера: `Examples/stm32_display_backend_example.c`.

## Контракт дисплея и DMA

`HmiDisplay.write_rect(x,y,w,h,pixels,stride,user)` получает логический прямоугольник 320×480. `stride` измеряется в пикселях, не байтах. `pixels` содержит значения `uint16_t RGB565` в порядке CPU; драйвер формирует порядок байтов на проводе и при необходимости RGB666.

Callback **синхронный по времени жизни буфера**: до возврата передача должна закончиться. Можно запустить DMA и ждать его завершения, но нельзя вернуть управление с активным DMA: следующий блок затрёт пиксели. Для полностью асинхронного вывода понадобится дополнительный собственный буфер и отдельный протокол владения им; текущий API не обещает перекрытие рендера с DMA.

Драйверу остаются установка адресного окна, передача пикселей и ожидание окончания. При переходе SPI → FSMC/8080 меняется только эта реализация. Инициализацию конкретного LCD выполняет плата до `hmi_ui_init`. Для Raspberry Pi LCD требуется проверить контроллер и обрамление SPI-команд по реальному модулю.

## Координаты и события касания

- Передавать координаты после калибровки: X 0…319, Y 0…479. Разворот дисплея учитывается здесь же.
- Вызывать примерно каждые 10 мс; передавать `pressed=0` после отпускания. Координаты на отпускании могут отсутствовать.
- Действие выполняется один раз при отпускании после минимум 20 мс. Удержание не повторяет его. Смещение более 12 пикселей или выход за экран отменяет жест. Прокрутка жестами не реализована.
- Модальное окно блокирует кнопки под ним. Новая сцена во время касания отменяет старую цель.
- XPT2046 может разделять SPI с LCD, но имеет отдельный CS и собственную частоту. Переключать настройки/CS только после окончания передачи LCD.
- Вызовы UI выполняются из одного foreground-контекста, не из ISR. У рендерера глобальные рабочие данные: поддерживается один активный экран/экземпляр UI.

## Что делает контроллер

Навигация по четырём страницам и разделам параметров; выбор строки управления и повторный тап для ввода; общий числовой редактор 42 значений; проверка диапазона и знака; часы; 16 HEX-цифр ROM каждого из пяти датчиков; выбор алгоритма, режима ШИМ и соединения двигателя; настройки видимости/единиц; диапазоны осей; выбор графика, масштаба времени и состояния ПУСК/СТОП графика; фильтр/страницы/экспорт/подтверждение очистки журнала; справка.

Вводимое значение остаётся черновиком до OK. Настройки флагов/единиц и вложенные пределы осей/управления остаются черновиками до «Сохранить» родительского окна. «Отмена» их отбрасывает. Скрытые поля и выбранные единицы применяются к главному экрану. Канонические значения событий: Гц, %, В, А и другие единицы из `HmiValueId`/таблицы `values` — изменение единиц отображения не меняет формат протокола.

Диапазоны ввода в `values` — настройки оболочки, их следует согласовать с проектом ПЧ. Защиты и допустимость команд проверяет основной контроллер. Библиотека не включает алгоритм управления двигателем и не запускает силовую часть самостоятельно.

Действия, требующие внешних данных/оборудования, выдают запросы: экспорт/очистка журнала, получение следующей страницы, автопределение, выбор языка, сохранение результатов. Приложение выполняет запрос и возвращает состояние/данные. Перевод всех экранов на английский, вычисление графических выборок, хранилище журнала и протокол связи не входят в оболочку.

`HMI_ACTION_CUSTOM` сохраняет стабильный ID: 1 — запрос языка, 10…12 — режим ШИМ, 20/21 — соединение двигателя, 30 — чётность, 300 — сохранить результаты автоопределения. Новое значение выбора находится в `event.value`. Запросы пуска/отмены автоопределения имеют отдельные типы событий; результат должен прийти от основного контроллера. Исходная сцена `params-auto` содержит демонстрацию уже выполняющегося процесса; кнопка в ней соответствует отмене, а новый запуск доступен через `HMI_ACTION_AUTO_START` и кнопку повторения завершённого процесса.

## Очередь и хранение

`HmiEvent`: `sequence`, `type`, `id`, `value`, `flags`, `data[8]`. Для ROM в `data` находятся 8 байт; для настройки панели — первые четыре индекса единиц, в `flags` — маска видимости. `HmiValueId` не является адресом Modbus: таблицу преобразования задаёт приложение.

Очередь содержит 16 событий. При переполнении удаляется самое старое; счётчик `event_overflows` увеличивается. `last_event` остаётся доступен после чтения очереди. Забирайте события каждый проход цикла, до медленных операций протокола. Счётчики и значения живут в RAM; сохранение между включениями выполняется приложением по событиям, например во Flash/EEPROM.

Не передавать C-структуру по UART напрямую: явно сериализовать поля, определить порядок байтов, представление float/фиксированной точки, адреса и подтверждения.

## Телеметрия

```c
HmiState old = ui.state;
ui.state.output_current = measured_current;
hmi_diff_and_invalidate(&old, &ui.state);
hmi_ui_render(&ui);
```

Массивы графиков, строки и журнал принадлежат приложению и должны оставаться действительными до конца отрисовки. Для журнала передавать срез текущей страницы (до 7 строк), применив фильтр `ui.settings[4]`. Если меняется содержимое по прежнему указателю, дифф этого не обнаружит: вызвать `hmi_invalidate` для области графика/журнала или `hmi_invalidate_all`. То же относится к ручному изменению `ui.parameters`, единиц и других полей `HmiUi`. Не копировать и не перемещать инициализированный `HmiUi`: `state.clock` ссылается на его внутреннюю строку.

## Расширение кнопок

`hmi_ui_set_regions` принимает постоянную таблицу `HmiTouchRegion` с прямоугольником, сценой, действием и аргументом. Она проверяется раньше встроенной карты. `HMI_SCENE_COUNT` означает все сцены, включая модальные — глобальные области добавлять осознанно. Для энкодера/физических кнопок есть `hmi_ui_dispatch` с той же логикой и событиями.

Новый числовой параметр добавляется в `HmiValueId` и общую таблицу `values`, без копирования клавиатуры и обработчика. Геометрию старого экспорта можно посмотреть через `Scripts/inspect_layout.py`.

## Сборка и воспроизводимость

```sh
make -j2
make test
make references                 # пересоздать уплотнённые C-таблицы
python3 Scripts/measure_size.py   # размеры объектных секций, без host CRT
```

Windows/MinGW: `mingw32-make -j2 PYTHON=C:/path/to/python.exe`, затем такая же команда с `test`. Собирается с `-std=c99 -Os -Wall -Wextra -Werror`.

Рабочий буфер по умолчанию 2048 пикселей = 4096 байт. Настройка: `CPPFLAGS="-Iinclude -DHMI_RENDER_BUFFER_PIXELS=5120"`. Минимум — 320 пикселей. Размеры ARM ELF и стека необходимо проверить в конечном проекте, особенно с float-форматированием (`snprintf`; newlib-nano может потребовать `-u _printf_float`).

`Scripts/pack_assets.py --import-dir PATH` импортирует прежний формат C-экспорта. Исходные числа сохраняются в воспроизводимом gzip JSON; это вход генератора, а не дополнительная копия данных в прошивке. Полный профиль не удаляет шрифты, символы или сцены; ограничения компактного профиля описаны в PROFILES.md. После импорта запустить `python Scripts/generate_profiles.py`. Исходного HTML/экспортёра в клонированном репозитории не было.

Опциональное поле `runtimeUi` в editor JSON описывает новую компактную раскладку сенсоров и числовые поля. Существующие статические editor overrides сохранены. Поддержка runtime-слоя в Android preview потребует изменения Android-приложения, которого в этом репозитории нет; фактический C-preview: `build/ui_preview preview.ppm 4`.
