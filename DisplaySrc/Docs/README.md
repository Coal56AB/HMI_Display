# ПЧ-1000: C99 UI 320×480 RGB565

Переносимый рендерер и оболочка сенсорного управления для STM32. Полного framebuffer, HAL и зависимости от SPI/FSMC в библиотеке нет.

**[Подключение к STM32 и контракт API](INTEGRATION.md)** · **[Измерения и проверки](TEST_RESULTS.md)**

```sh
make -j2
make test
```

На Windows использовать MinGW `mingw32-make` и при необходимости `PYTHON=C:/path/to/python.exe`.

## Сжатие без потери исходного изображения

- Сохранены 47 сцен, все 4224 глифа, 22 шрифта и 4-битное сглаживание.
- 9598 примитивов используют 336 общих шаблонов и компактные переопределения параметров. Линии графиков хранят приращения координат.
- Шрифты используют общий алфавит, 8-байтовые записи глифов, дедупликацию bitmap и RLE там, где оно экономит место. Обычный и выровненный текст используют одну функцию рисования глифа.
- Весь исходный рендерер: 495 504 → 335 008 байт code/const в одинаковой host-сборке `-Os` (−32,4%). Вместе с новой оболочкой касаний: 353 520 байт (−28,7% к исходному рендереру).
- Буфер пикселей: 10 240 → 4096 байт. Рендерер: 4736 байт статической RAM; отдельный `HmiUi`: 1344 байта на x64 host, плюс стек/прикладные данные.

Эти размеры не являются размером ARM-прошивки: драйверы, приложение, библиотеки и стек измеряются в итоговом STM32-проекте. В F103C8 с 64 КБ Flash полный комплект всё ещё не помещается; для F103 с 512 КБ появился существенный запас по сравнению с исходной версией.

## Сенсорная оболочка

```c
hmi_ui_init(&ui, (HmiDisplay){ display_flush, display_user });
hmi_ui_touch(&ui, x, y, pressed, now_ms);
hmi_ui_render(&ui);
while (hmi_ui_poll_event(&ui, &event)) {
    // Сериализовать нужные события в протокол проекта.
}
```

Есть навигация, числовой/HEX-ввод, время, настройки, отмена и сохранение, очередь событий и расширяемая карта касаний. Координаты подаются после калибровки сенсора. Драйвер LCD принимает прямоугольник RGB565: при переходе с SPI на параллельную шину логика UI не меняется.

Команды, которым нужны данные или силовой контроллер, передаются приложению событиями. Точная граница ответственности, время жизни DMA-буфера, единицы значений, переполнение очереди и обновление телеметрии описаны в `INTEGRATION.md`.

## Генерация и тесты

`make references` воспроизводит уплотнённые C-таблицы из `Assets/asset_source.json.gz`. Для свежего старого C-экспорта: `python3 Scripts/pack_assets.py --import-dir PATH`, затем `python3 Scripts/generate_profiles.py`. Эти исходные данные не включаются в прошивку.

В исходном checkout отсутствовали заявленные HTML-эталоны и тесты. Добавленные регрессионные тесты сравнивают с неизменённым C-рендерером исходного коммита, а не с отсутствующим HTML. Статические сцены совпадают попиксельно; новый runtime-слой касаний имеет отдельные тесты и C-preview.
