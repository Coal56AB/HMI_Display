# Проверка настоящего экрана через USB

ПК имитирует основную STM32: передаёт состояние шести моторов, положение мелодии,
MIDI-события и отвечает на команды сенсорного экрана. Отрисовка выполняется на
настоящем ESP32 и дисплее, поэтому здесь видна фактическая скорость SPI.

## Запуск

1. Собрать и прошить ESP32 единой прошивкой `display` из корня этого субмодуля:

   ```powershell
   ./Firmware/ESP32/build.ps1 -Environment display -Upload -Port COM7
   ```

   Вместо COM7 указать свой порт. При необходимости вход в загрузчик:
   удерживать BOOT, нажать и отпустить RESET, затем отпустить BOOT.
2. Подключить единственный USB-C ESP32-S3 к ПК кабелем с передачей данных и нажать RESET.
   При загрузке прошивка определит ПК и включит USB-симулятор.
3. Запустить `USB_SIMULATOR.cmd`. Откроется обычное окно приложения Qt.
4. Выбрать COM-порт ESP32 и нажать «Подключить», затем «Играть».
   Можно загрузить `.mid` или подавать отдельные ноты. На физическом экране
   открыть страницу MIDI: шкала и ноты движутся во время воспроизведения.
5. Проверить на экране паузу, стоп, перемотку и управление моторами после
   остановки мелодии. После «СТОП ВСЁ» сначала активировать драйверы.
   Страница ПК показывает полученные от экрана команды.
6. Закрытие окна останавливает симулятор и освобождает COM-порт.

При первом запуске устанавливаются `pyserial`, `mido` и `PySide6` в существующее окружение
сборки `.build/platformio/core`. Отдельного виртуального окружения не создаётся.
Без подключённого ESP можно проверить воспроизведение в окне приложения.
Кнопка «Подключить» открывает выбранный COM-порт напрямую. Если порт занят,
ошибка показывается в окне; закрой монитор порта и другие программы с этим портом.

## UART имеет приоритет

| ESP32-S3 | Основная STM32F103 |
| --- | --- |
| GPIO5, TX UART1 | PA10, RX USART1 |
| GPIO4, RX UART1 | PA9, TX USART1 |
| GND | GND |

UART: 921600, 8N1, логические уровни 3,3 В. Цифры 4 и 5 — маркировка GPIO
на показанной компактной плате. LCD RST подключён к GPIO6.

В основной прошивке `firmware/Core/Src/protocol.c` добавлена передача HMI-состояния
и обработка команд при `LIVE_MIDI_MODE=1`. Старую прошивку STM32 нужно обновить,
чтобы она отвечала этому экранному режиму. Для USB-проверки STM32 вообще не нужна.
NOTE_SET остаётся совместимым; свежий MIDI запрещает ручные команды, кроме стопа.
STM32 сообщает реальные состояния моторов; загрузка песен и перемотка относятся
к ПК-симулятору, на STM32 эти команды возвращают «недоступно».

Первый корректный STATE по UART немедленно переключает экран на STM32.
USB продолжает приниматься в отдельный буфер, но не управляет экраном.
Через 500 мс без корректного STATE по UART экран возвращается к свежим USB-данным.
Если обоих источников нет, отображается отсутствие связи. Заголовок показывает
`UART` или `USB TEST`. Команды уходят только текущему источнику; при переключении
незавершённые команды и история старого источника сбрасываются.

ESP отправляет heartbeat по UART каждые 100 мс. STM32 останавливает ручное
управление при утрате полномочий или heartbeat более чем на 300 мс.
Ноты USB-симулятора на UART не пересылаются.

## Одна прошивка, два USB-режима

Рабочая прошивка — `display`. При загрузке ESP в течение секунды проверяет
наличие USB-хоста ПК. С ПК работает USB-симулятор; без ПК запускается USB MIDI Host.
После смены кабеля нажать RESET либо удержать BOOT 2 секунды и отпустить.
Переключение сопровождается перезапуском ESP, перепрошивка не требуется.
Одновременная работа с ПК и MIDI-инструментом через один USB PHY не поддерживается.
UART и полный GUI доступны в обоих режимах. Без обратной связи STM32 в режиме
MIDI Host экран показывает отправляемые логические голоса, с подписью «USB MIDI».

`template` оставлен только как минимальный проект дисплея для ветки templates;
для музыкальной шкатулки выбирать его не нужно.

## Проверки исходников

MIDI-диаграмма и шкалы используют диапазон, соответствующий 20–1200 Гц;
на диаграмме подписаны ноты E0–D6. Диаграмма обновляется
слева направо: сравнение с точным предыдущим изображением, отправка только
изменившихся пикселей. Сохранённые ноты остаются историей до выхода за окно времени.

ESP самостоятельно удерживает значок, шкалу и подпись ноты на главном экране
для всех источников (UART, USB, локальный MIDI). Минимальное время показа — 1000 мс;
затем, начиная с max(начало+1000 мс, Note Off), ещё 1000 мс ожидается следующая нота.
Если она приходит раньше погасания, индикация остаётся включённой с новой нотой.
Например, нота 0–100 мс без продолжения гаснет на главном экране в 2000 мс.
Это локальное ожидание: будущие события по текущему протоколу ESP не получает.
Сон, сброс, исключение мотора из установленного набора, пауза и потеря связи снимают удержание.
Диаграмма MIDI и управление моторами всегда следуют фактическим событиям без задержки.
ПК передаёт только фактические состояния; прежние биты удержания 0x08/0x10 ESP игнорирует.
