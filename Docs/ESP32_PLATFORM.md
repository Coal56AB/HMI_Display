# Граница платформы ESP32

`Firmware/ESP32` — самостоятельный проект LCD ILI9486 и сенсора XPT2046.
Его исходники одинаковы в `templates` и прикладной ветке. Он не содержит
музыкального протокола, USB-MIDI, памяти композиций или настроек приложения.

## Подключение приложения

Сборка `display` подключает `DisplaySrc/esp32/CMakeLists.txt`, если он существует.
Расширение добавляет исходники, include-пути, зависимости и defines через
`hmi_sources`, `hmi_includes`, `hmi_requires`, `hmi_defines`.
Сборка `template` всегда использует цветные полосы и крестик касания.
Без расширения сборка `display` использует ту же демонстрацию.

`main/hmi_module.h` объявляет необязательные точки расширения:

1. `hmi_module_configure(DisplayPlatform *)` — подключение сервисов приложения
   после инициализации LCD/тача, до проверки ресурсов и инициализации GUI.
2. `hmi_module_start()` — подготовка приложения до запуска GUI; false останавливает запуск.
3. `hmi_module_run()` — запуск фоновых задач после `display_init`.
4. `hmi_module_tick(now)` — доставка событий приложения перед очередным `display_step`.

В платформе используются пустые реализации. Она предоставляет вывод RGB565,
геометрию, время и перезапуск. Сервисы ресурсов, Flash и отправки данных по умолчанию
равны NULL. Приложение подключает их через `configure`. Проверка ресурсов
использует уже настроенный `DisplayPlatform`.

## Таблица разделов

`Firmware/ESP32/partitions.csv` содержит только служебные NVS/PHY и приложение.
Прикладное расширение может предоставить свою `DisplaySrc/esp32/partitions.csv`.
При сборке через PlatformIO `module_config.py` выбирает её только для `display`
с существующим расширением. `template` всегда использует базовую таблицу.
Изменять общий код или базовую разметку для конкретного приложения не требуется.

Размер Flash, GPIO дисплея и калибровка сенсора относятся к конфигурации платы;
адреса прикладных настроек, форматы записей и перенос старых данных — к приложению.

## Отрисовка и ввод

Общий `Firmware/Api/display_renderer.h` управляет канвой и обновлениями.
Драйвер дополнительно пропускает неизменившиеся полные блоки 16×8 по 64-битным
сигнатурам; узкие прямоугольники передаёт напрямую. SPI DMA завершает передачу
до возврата, после чего буфер можно переиспользовать.

Сенсор передаёт события `display_event` из задачи интерфейса между обновлениями.
Приложение не должно вызывать отрисовку из фоновых задач. Для их взаимодействия
используется принадлежащая приложению очередь событий.

`hmi_debug` содержит счётчики прямоугольников, пикселей и касаний, длительность
передач, сырые и экранные координаты. Параметры опроса и калибровки находятся
в `main/board_config.h`.
