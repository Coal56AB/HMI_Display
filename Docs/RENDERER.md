# Общий модуль отрисовки

`Firmware/Api/display_renderer.h` содержит очередь обновлений, объединение
областей, буферы полос, обход экрана, поворот и точное сравнение пикселей.
Это переносимый C-код без HAL и динамического выделения памяти. Реализация
находится в заголовке: Keil, ESP-IDF и симуляторы подключают одинаковый код
без дополнительных исходников в манифесте интерфейса. Контракт `DisplayPlatform`
и версия API 2 остаются прежними.

## Реализация интерфейса

Интерфейс хранит состояние страниц, обрабатывает события, рисует содержимое
в `DisplayCanvas` и отмечает области, где могло измениться изображение.
Он не сравнивает кадры, не объединяет прямоугольники передачи и не управляет SPI.

```c
#include "display_renderer.h"

DISPLAY_RENDER_STORAGE(storage, 480 * 16, 0);
static DisplayRenderer renderer;

static void paint(DisplayCanvas *canvas, void *user) {
    (void)user;
    display_canvas_fill(canvas, 0, 0, 480, 320, 0);
    /* Кнопки, текст и другие элементы интерфейса. */
}

void display_init(const DisplayPlatform *platform) {
    display_renderer_init(&renderer, platform, 480, 320, storage, 0);
    display_renderer_full(&renderer);
}

void display_step(uint32_t now_ms) {
    (void)now_ms;
    DisplayRenderStyle style = {DRAW_TOP_TO_BOTTOM, {0,0,0,0}, 0, 0};
    display_renderer_step(&renderer, paint, 0, &style);
}
```

`paint` заполняет весь переданный `canvas->clip` текущим изображением.
Координаты рисования логические; `display_canvas_fill` обрезает примитивы по clip.
Для своих примитивов доступны `canvas->pixels` и ширина строки `canvas->clip.w`.
Канва и её буфер действуют только до возврата из callback.

После изменения состояния вызывайте
`display_renderer_invalidate(&renderer, x, y, w, h)`.
Для смены страницы — `display_renderer_full`. Один вызов `step` обрабатывает
одну полосу; `display_renderer_pending` возвращает число оставшихся областей.
Обработку событий выполняйте между вызовами `step`, не внутри paint или write_rect.
`display_renderer_clear` очищает очередь и сбрасывает кеш изображения.

## Направление

`DisplayRenderStyle.direction` задаёт порядок полос в логических координатах:
`DRAW_TOP_TO_BOTTOM`, `DRAW_BOTTOM_TO_TOP`, `DRAW_LEFT_TO_RIGHT`,
`DRAW_RIGHT_TO_LEFT`. Настройки можно возвращать из функции конкретного интерфейса
и передавать в `step`. При NULL используются полосы сверху вниз без кеша.

Общий модуль сам выбирает размер полосы по ёмкости буфера; вертикальные полосы
ограничены 32 столбцами. Ёмкости должно хватать хотя бы на одну полную строку
и один полный столбец. Если физическая геометрия экрана переставлена относительно
логической, модуль поворачивает прямоугольники и пиксели на 90° по часовой стрелке.
Направление обхода и поворот экрана — отдельные операции.

## Точное сравнение пикселей

Для области с палитрой до 15 цветов RGB565 задайте `cache_area`, `palette`
и `palette_count`. Размер хранилища кеша в `DISPLAY_RENDER_STORAGE` и `init` —
`(width * height + 1) / 2` байт для этой области. Например, для MIDI-графика
480×210 нужно 50 400 байт. Модуль хранит по четыре бита на пиксель, сравнивает
новое изображение и передаёт прямоугольники только из изменившихся пикселей.

Первое изображение, пиксели вне области кеша и цвета вне палитры передаются
без пропуска. Изменение области или содержимого палитры, отключение кеша
и повторная инициализация сбрасывают предыдущие значения. Без кеша передаются
отмеченные интерфейсом области целиком, с разбиением на полосы.

На ESP32 дополнительно действует фильтр `LcdDamage` в драйвере: он пропускает
неизменившиеся полные блоки 16×8 по хешам. Это отдельный уровень сокращения
передач; узкие прямоугольники передаются напрямую. Полный кадровый буфер не нужен.

## Примеры и проверки

- `Firmware/Api/display_empty.c` — пустой модуль с канвой и общим циклом; начальное
  обновление не запрашивается, поэтому терминалка запуска остаётся видимой.
- `Firmware/ESP32/main/template_demo.c`, если присутствует ESP32-платформа, —
  цветные полосы и крестик касания; обновляет старую и новую области крестика.
- `Scripts/Check/native_renderer_test.c` — четыре направления, поворот,
  точные дельты, неизвестные цвета, смена палитры, сброс кеша и очередь обновлений.
  Собирается обычным компилятором C11 без прошивки устройства.
