# Контракт сменного интерфейса

Модуль выбирается аргументом `--display-dir`; по умолчанию это `DisplaySrc`.
Его каталог может находиться вне этого репозитория. `module.json` содержит `apiVersion: 1`,
`name`, `assets`, `resourceBuild`, `simulator` и секцию `firmware` со списками
`sources`, `includes`, `defines`. Все пути внутри описания относительны каталогу модуля.

Общая прошивка включает только `display_module.h`, предоставленный модулем.
Она не использует типы страниц, структуры GUI и команды конкретного устройства.

| Группа | Функции модуля |
|---|---|
| Жизненный цикл | `display_init`, `display_poll`, `display_render` |
| Сенсор | `display_touch(x, y, down, now)` |
| Входящий транспорт | `display_receive`, `display_receive_error` |
| Ресурсы | `display_assets_init`, `display_assets_error`, `display_assets_size` |
| Диагностика чтений | `display_asset_loads_reset`, `display_asset_loads` |
| Буфер стартовой консоли | `display_console_begin`, `display_console_pixel`, `display_console_pixels` |

`display_init` получает функцию записи прямоугольника RGB565, а `display_assets_init` —
функцию чтения внешней памяти. Буфер консоли использует память модуля, поэтому платформа
не выделяет второй framebuffer. Этот буфер должен работать до проверки внешних ресурсов.

Платформа предоставляет `display_transport_send` и `display_system_reset`.
STM32-адаптер модуля может использовать общие операции `board_flash_read/write/erase`.
Распределение внешней памяти и формат содержимого выбирает модуль; он обязан исключать
пересечение ресурсов с собственными сохраняемыми данными.

Координаты касания и время передаются как измеренные платформой данные. Выбор страницы,
одиночное/двойное нажатие и назначение зон определяются модулем. Парсер и смысл UART-пакетов
также принадлежат ему. Байты принимаются из IRQ, применение изменений — в основном цикле.

Симулятор, его зависимости, интерфейс ПК и сборочные скрипты полностью принадлежат модулю.
Чтобы подключить другой GUI, реализуйте этот контракт и укажите свои файлы в `module.json`.
